# Quest & Objectives Frontend Integration Guide

This document provides a comprehensive guide for the frontend team (React/TypeScript) to integrate the new real-time **Quest and Objective** management system.

---

## 1. TypeScript Models (`src/models/Quest.ts`)

Mirror these types and interfaces in your React project:

```typescript
export enum QuestType {
  Main = "Main",
  Side = "Side",
  Faction = "Faction",
  Personal = "Personal",
  Undefined = "Undefined"
}

export enum QuestStatus {
  Available = "Available",
  Unavailable = "Unavailable",
  Active = "Active",
  Completed = "Completed",
  Failed = "Failed"
}

export interface QuestObjective {
  id: string;                  // MongoDB ObjectId (generated by backend)
  description?: string;        // Short goal text
  isCompleted: boolean;        // True if objective has been finished
  currentProgress: number;     // Current numerical progress count
  completionThreshold: number; // Target numeric goal (defaults to 1)
}

export interface Quest {
  id?: string;                        // MongoDB ObjectId (generated by backend)
  campaignId: string;                 // Association with active Campaign
  involvedCharacterIds?: string[];    // Linked Character ObjectIds (used for Personal Quests)
  title: string;                      // Name of the quest
  description?: string;               // Lore, context, or notes
  location?: string;                  // Area, town, or plane name
  objectives: QuestObjective[];       // Embedded list of goals
  status: QuestStatus;                // Current state
  type: QuestType;                    // Type of quest
  rewardItemIds: string[];            // Loot items awarded
  rewardCurrency: {                   // Cash reward
    gold?: number;
    silver?: number;
    copper?: number;
  };
  createdAt?: string;                 // ISO Date String (audited)
  updatedAt?: string;                 // ISO Date String (audited)
}
```

## 2. REST Endpoints (`api/quest`)

All requests require Bearer token authorization. Headers should include: `Authorization: Bearer <token>`.

### Quest Management

#### Get Quest by ID
*   **Method:** `GET`
*   **Path:** `/api/quest/{id}`
*   **Response (200 OK):**
    ```json
    {
      "data": { ...QuestObject },
      "message": "Quest retrieved successfully."
    }
    ```

#### Get Campaign Quests
*   **Method:** `GET`
*   **Path:** `/api/quest/campaign/{campaignId}`
*   **Response (200 OK):**
    ```json
    {
      "data": [ { ...QuestObject }, ... ],
      "message": "Quests retrieved successfully."
    }
    ```

#### Create Quest
*   **Method:** `POST`
*   **Path:** `/api/quest`
*   **Body:** `Quest` object (omit `id`).
*   **Response (200 OK):**
    ```json
    {
      "data": { ...CreatedQuestObject },
      "message": "Quest created successfully."
    }
    ```

#### Update Quest
*   **Method:** `PUT`
*   **Path:** `/api/quest/{id}`
*   **Body:** Full updated `Quest` object.
*   **Response (200 OK):**
    ```json
    {
      "data": { ...UpdatedQuestObject },
      "message": "Quest updated successfully."
    }
    ```

#### Delete Quest
*   **Method:** `DELETE`
*   **Path:** `/api/quest/{id}`
*   **Response (200 OK):**
    ```json
    {
      "message": "Quest deleted successfully."
    }
    ```

### Atomic Objective Management (Recommended)

To avoid sending the entire Quest back and forth, use these endpoints for atomic objective updates:

#### Add Objective
*   **Method:** `POST`
*   **Path:** `/api/quest/{questId}/objective`
*   **Body:**
    ```json
    {
      "description": "Exterminate the Wererats in the cellar",
      "currentProgress": 0,
      "completionThreshold": 4
    }
    ```
*   **Response (200 OK):** Returns the full updated `Quest` document with the new objective added (including its newly generated `id`).

#### Update Objective (Progress, Description, etc.)
*   **Method:** `PUT`
*   **Path:** `/api/quest/{questId}/objective`
*   **Body:**
    ```json
    {
      "id": "abc-123-guid-string", // REQUIRED to target the correct objective
      "description": "Exterminate the Wererats in the cellar",
      "currentProgress": 2,
      "completionThreshold": 4,
      "isCompleted": false
    }
    ```
*   **Response (200 OK):** Returns the full updated `Quest` document.
*   *Note:* The backend automatically marks the objective as `isCompleted = true` if `currentProgress >= completionThreshold`.

#### Delete Objective
*   **Method:** `DELETE`
*   **Path:** `/api/quest/{questId}/objective/{objectiveId}`
*   **Response (200 OK):** Returns the full updated `Quest` document with the objective removed.

## 3. Security, Authorization & Roles

The backend enforces strict rules on who can modify quests. Hide/disable buttons on the frontend according to these guidelines to optimize user experience:

*   **Dungeon Masters (DMs) & System Admins** can manage **all** quests and objectives in the campaign.
*   **Players** have restricted access:
    *   They **CANNOT** create, update, delete, or manage objectives for `Main`, `Side`, or `Faction` quests (Status 403 Forbidden).
    *   They **CAN** create, update, delete, and manage objectives for **Personal Quests** (`type: 3`), provided they own **at least one** of the characters in the `involvedCharacterIds` list.
    *   They can add other campaign characters to `involvedCharacterIds` to create **Collaborative/Shared Personal Quests**. All owners of those listed characters will have management rights.
    *   Cross-campaign exploitation is fully blocked: any added character ID must belong to the same campaign as the quest, or the server returns an error.

## 4. SignalR Real-Time Synchronization

The backend broadcasts quest changes instantly. Register a listener on your SignalR client connection:

```typescript
import { HubConnection } from "@microsoft/signalr";

interface EntityChangePayload {
  entityType: string; // "Quest"
  entityId: string;   // The affected Quest ID
  action: "created" | "updated" | "deleted";
  data: any;          // The actual Quest object (or { id: string } for deletion)
  changedBy: string;  // Username of actor
  timestamp: string;  // ISO string
}

export const setupQuestListeners = (connection: HubConnection) => {
  connection.on("EntityChanged", (payload: EntityChangePayload) => {
    if (payload.entityType !== "Quest") return;

    console.log(`Quest change by ${payload.changedBy}:`, payload);

    switch (payload.action) {
      case "created":
        // payload.data is the full created Quest object
        dispatchEvent(new CustomEvent("QUEST_CREATED", { detail: payload.data }));
        break;
      case "updated":
        // payload.data is the full updated Quest object
        dispatchEvent(new CustomEvent("QUEST_UPDATED", { detail: payload.data }));
        break;
      case "deleted":
        // payload.data is { id: "questId" }
        dispatchEvent(new CustomEvent("QUEST_DELETED", { detail: payload.entityId }));
        break;
    }
  });
};
```

### Recipient Distribution Logic:
The backend automatically targets:
1. All Dungeon Masters/owners of the campaign.
2. All players who own characters currently in the campaign.
3. The user who made the change is excluded (`excludeUserId`) to prevent redundant local state updates.
